Proyecto académico · 2026

1. Introducción

Task University es una aplicación web full-stack orientada a la organización de tareas académicas. El sistema permite autenticar usuarios, administrar tareas y categorías, consultar indicadores de productividad y mantener un registro de auditoría sobre las operaciones relevantes.

La solución fue diseñada para ejecutarse en un entorno local con XAMPP como proveedor de MySQL. El frontend ofrece una interfaz de trabajo para estudiantes y administradores, mientras que el backend expone una API REST protegida mediante JSON Web Tokens.

2. Objetivos

2.1 Objetivo general

Desarrollar un sistema web formal y funcional que facilite la planificación, seguimiento y administración de tareas académicas.

2.2 Objetivos específicos

  • Implementar autenticación segura con usuario, contraseña y tokens JWT.
  • Permitir crear, consultar, editar, eliminar y completar tareas.
  • Organizar tareas mediante estados, prioridades, fechas límite y categorías.
  • Proporcionar un dashboard con indicadores de avance y productividad.
  • Separar permisos de usuarios y administradores.
  • Registrar acciones relevantes mediante auditoría.
  • Automatizar validaciones, pruebas y build mediante CI/CD.

3. Desarrollo

3.1 Descripción del proyecto

La aplicación cuenta con dos módulos principales. El frontend, construido con React y Vite, gestiona la experiencia de usuario, formularios, filtros, modales, navegación y consumo de la API. El backend, construido con Node.js y Express, concentra las reglas de negocio, autenticación, autorización y persistencia en MySQL.

3.2 Arquitectura utilizada

Se utiliza una arquitectura cliente-servidor dividida en capas. El navegador ejecuta el cliente React y consume endpoints REST del backend. Express dirige las solicitudes hacia controladores, los modelos encapsulan las consultas SQL y MySQL almacena la información persistente.

[ Usuario ] | v [ Frontend React + Vite ] ---> [ API REST Express ] | [ Middleware JWT ] | [ Controladores ] | [ Modelos ] | [ MySQL / XAMPP ] [ GitHub Actions | GitLab CI/CD | Azure Pipelines ] validacion -> pruebas -> build -> despliegue

Flujo de autenticación

  1. El usuario envía sus credenciales a /api/auth/login.
  2. El backend valida la contraseña con bcryptjs.
  3. Se genera un token JWT y se registra el acceso en auditoría.
  4. El frontend guarda el token y lo envía en cada solicitud protegida.
  5. El middleware valida el token antes de permitir el acceso al recurso.

3.4 Integración continua y despliegue

Los pipelines se ejecutan cuando hay cambios en las ramas principales o Pull Requests. Primero instalan dependencias, validan la sintaxis del backend, ejecutan el test automatizado, aplican ESLint al frontend y generan el build de producción. El resultado se publica como artefacto y puede desplegarse en GitHub Pages, GitLab Pages o Azure Static Web Apps según la configuración del proveedor.

3.5 Conclusión técnica

La solución separa claramente presentación, servicios HTTP, reglas de negocio y persistencia. Esta separación facilita el mantenimiento, permite validar cada parte de forma independiente y ofrece una base adecuada para ampliar reportes, notificaciones y funcionalidades académicas futuras.
